# The web edition as an agent-ready site

The book teaches how to make a website work for AI agents, so its own web edition does what the book teaches. Everything on this page is generated by the site build from the manuscript and [`tools/book.json`](tools/book.json); nothing is written by hand per chapter. The code is in [`tools/agent_ready.py`](tools/agent_ready.py) (the files agents read), [`tools/build_site.py`](tools/build_site.py) (the pages) and [`theme/site/webmcp.js`](theme/site/webmcp.js) (the in-page tools).

Checked on 2 November 2026 against the two scanners the book uses: [isitagentready.com](https://isitagentready.com/) (its check list as returned by `POST https://isitagentready.com/api/scan` for https://webmcp.salnikov.no at 2026-11-02T21:01Z) and Lighthouse 13.6.0's **Agentic browsing** category ([scoring documentation](https://developer.chrome.com/docs/lighthouse/agentic-browsing/scoring), retrieved 2026-11-02).

## What the site publishes

| What | Where | Who reads it |
| --- | --- | --- |
| Semantic HTML: `lang`, landmarks, one `<h1>` per page, a skip link, a labelled contents navigation, a real `<form role="search">` | every page | browsers, screen readers, agents that read the accessibility tree |
| A Markdown version of every page, with `<link rel="alternate" type="text/markdown">` and a `Link` header pointing to it | `/<page>.md`, `/index.md` | agents that prefer text to HTML |
| `llms.txt` in the [llmstxt.org](https://llmstxt.org/) format: title, summary, one link per part, chapter and appendix (to its `.md`), with a one-line description each | `/llms.txt` | language models and agents |
| The whole book as one Markdown file, in reading order | `/llms-full.txt` | agents that want everything at once |
| `robots.txt` with a `Content-Signal` line in every group, AI crawlers listed by purpose (search, user-triggered, training) | `/robots.txt` | crawlers |
| `sitemap.xml` with `<lastmod>` (the release date of the version on the site) | `/sitemap.xml` | search engines |
| An Atom feed of the releases, from `CHANGELOG.md` | `/releases.xml` | feed readers, agents watching for updates |
| JSON-LD: schema.org `Book` (author `Person` with `sameAs`, `hasPart` chapters) on the home page; `Chapter` and `BreadcrumbList` on every page | `<script type="application/ld+json">` | search engines, agents |
| An agent skill that tells an agent how to read, search and cite the book, in an [Agent Skills discovery index](https://schemas.agentskills.io/discovery/0.2.0/schema.json) (v0.2.0) with the skill's SHA-256 digest | `/.well-known/agent-skills/index.json`, `/.well-known/agent-skills/read-this-book/SKILL.md` | agents |
| An ARD manifest ([Agentic Resource Discovery](https://agenticresourcediscovery.org/spec/)) listing the skill, linked with `<link rel="ard">` and a `Link` header; the legacy `ai-catalog.json` name too | `/.well-known/ard.json`, `/.well-known/ai-catalog.json` | agents and registries |
| A table of contents as JSON, and the client-side search index | `/toc.json`, `/search-index.json` | the WebMCP tools, agents |
| WebMCP tools (below) | every page | agents in the browser |
| `Link` headers on every page (Markdown alternate, `llms.txt`, the feed; on the home page also the sitemap, the ARD manifest and the skills index) | `staticwebapp.config.json` routes, generated | agents that read headers before the body |

The `.well-known` files are written twice, to `.well-known/` and `well-known/`, and `staticwebapp.config.json` rewrites the first to the second. Static Web Apps documentation does not say whether it serves files from a folder whose name starts with a dot, and the rewrite works either way. (UNVERIFIED on a live Static Web App until the first deploy; the deploy workflow's smoke test requests `/.well-known/ard.json` and `/.well-known/agent-skills/index.json` and prints the status codes.)

## WebMCP tools

`theme/site/webmcp.js` feature-detects `document.modelContext` and does nothing in browsers without it. It uses the API as Chrome documents it in November 2026 (the same API the companion book *Tools, Not Clicks* teaches):

- **`search_book`** is a declarative tool: the search form on every page carries `toolname="search_book"`, `tooldescription`, `toolparamdescription` on its input and `toolautosubmit`. Without an agent it is an ordinary form that opens `search.html?q=…`. When an agent submits it, `webmcp.js` answers the `submit` event (`SubmitEvent.agentInvoked`, `respondWith()`) with the top ten results as JSON, without navigating away.
- **`list_chapters`** (read-only) returns every part, chapter and appendix with its number, title, page URL, Markdown URL, word count and section headings.
- **`get_chapter`** (read-only) returns the Markdown of one chapter by number, appendix letter or slug, cut at `max_chars` (1,000 to 200,000; the result says when it was cut). An unknown chapter returns an `error` and a `hint` instead of throwing, so the agent sees why.

Both imperative tools are registered with `readOnlyHint: true` and an `AbortSignal`. Tested on 2 November 2026 in Chromium 156.0.8078.4 with `--enable-features=WebMCPTesting`: `getTools()` listed all three tools on a chapter page, and `executeTool()` returned results for each.

Outside the testing flag, WebMCP runs in Chrome only for origins registered in the WebMCP origin trial (Chrome 149 to 162, per the Chrome origin-trial announcement of 9 June 2026: https://developer.chrome.com/blog/ai-webmcp-origin-trial). To join it:

1. Register `https://agent-ready-web.salnikov.no` for the WebMCP trial at https://developer.chrome.com/origintrials/ (one token per origin).
2. Put the token in `"origin_trial_token"` under `"agent_ready"` in `tools/book.json`. The build adds `<meta http-equiv="origin-trial">` to every page. It stays out while the value is empty.
3. Renew the token when Chrome asks. The trial ends with Chrome 162.

## Settings (one place)

All of it is configured under `"agent_ready"` in `tools/book.json`:

- `content_signal`: the line every robots.txt group carries. The default is `search=yes, ai-input=yes, ai-train=no`: the book may be indexed and used to answer questions (with a link), not used to train models. The syntax is the Content Signals Policy's (https://contentsignals.org/, and the IETF draft https://datatracker.ietf.org/doc/draft-romm-aipref-contentsignals/, both retrieved 2026-11-02).
- `training_crawlers`: `follow-content-signal` blocks the training crawlers in `ai_crawlers.training` with `Disallow: /` when `ai-train=no`, and allows them when it is `yes`. `ai_crawlers` lists the crawler user agents by purpose.
- `llms_full_txt`, `markdown_pages`, `json_ld`, `feed`, `agent_skill`, `ard_manifest`, `webmcp.imperative_tool`, `webmcp.declarative_form`: switch each layer off with `false`.
- `publisher_domain`: the domain in the ARD entry's URN (`urn:air:salnikov.no:books:…`).
- `origin_trial_token`: see above.

## isitagentready.com

The checks below are the ones isitagentready.com returned on 2 November 2026. "Expected" means the file or header is in the build and was checked locally against `tools/serve.py`; the live scan can only run after the first deploy (`curl -s -X POST https://isitagentready.com/api/scan -H 'content-type: application/json' -d '{"url":"https://agent-ready-web.salnikov.no"}'`).

| Check | Status | Why |
| --- | --- | --- |
| robots.txt | expected pass | generated |
| sitemap | expected pass | generated, with lastmod |
| Link headers | expected pass | generated per page |
| robots.txt AI rules | expected pass | AI crawlers named by purpose |
| Content Signals | expected pass | `Content-Signal` in every group |
| Agent Skills index | expected pass | `/.well-known/agent-skills/index.json` v0.2.0 |
| ARD | expected pass | `/.well-known/ard.json`, `rel="ard"`, Link header |
| WebMCP | expected pass once the origin-trial token is set; the scanner's browser must have WebMCP on | three tools on page load |
| Markdown negotiation (`Accept: text/markdown` on the same URL) | skipped | Static Web Apps static routes can't vary the response by the `Accept` header; it needs a proxy or a function. The site offers the same Markdown at `<page>.md`, announced by `rel="alternate"` and `Link`. |
| DNS-AID | skipped | DNS records for AI discovery; a DNS change, and the site has no agent endpoint to announce beyond its files. Revisit when the book's DNS chapter settles on a recommendation. |
| API Catalog (RFC 9727), OAuth / OIDC discovery, OAuth Protected Resource, auth.md | not applicable | the site has no API and no sign-in |
| MCP Server Card, A2A Agent Card, Personal Agent Protocol | not applicable | the site runs no MCP server or agent; a static book has nothing to serve over them. The demos repository shows them on the running example. |
| Web Bot Auth | informational | the site verifies no bots; it serves the same pages to everyone |
| Commerce (x402, MPP, UCP, ACP, AP2) | not applicable | not a commerce site (the scanner marks these neutral) |

For comparison, the companion book's site https://webmcp.salnikov.no scored level 1, "Basic Web Presence", on the same date (robots.txt and sitemap passed; Link headers, Content Signals, Markdown negotiation, Agent Skills, WebMCP and ARD failed).

```sh
python3 tools/build.py site
python3 infra/check_site.py dist/site            # CSP, Static Web Apps limits, JSON-LD, agent files

curl -sI http://localhost:8080/ | grep -i '^link:'
npx lighthouse@13.6.0 http://localhost:8080/ --only-categories=agentic-browsing \
  --chrome-flags="--headless=new --enable-features=WebMCPTesting" --output=json --output-path=lh.json
python3 tools/agentic_report.py lh.json
```
